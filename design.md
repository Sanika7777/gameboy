# NEOBRICK — Design Document

v1.0 · October 2026 · companion to `CLAUDE.md` (rules) and `phases.md` (build order)

---

## 1. Vision

NEOBRICK is a pocket console that never existed: retro constraints (a 160×144 LCD, four shades,
chip-style sound, eight buttons) with modern comforts (touch controls, instant load in a browser,
saves that survive a reload, swappable palettes, suspend/resume).

### Pillars

1. **Feels like hardware.** The console face is part of the UI. Buttons press in, the LCD can ghost,
   the boot screen chimes.
2. **Thumb-first.** Every game is fully playable with two thumbs on a phone in portrait. Keyboard is
   a secondary input.
3. **Pure C++, visible OOP.** The architecture is a teaching artifact. Each OOP concept lives where it
   naturally belongs, not in contrived demo code.
4. **Tiny and instant.** Under 2 MB total download, playable in under 2 s on 4G, 60 fps on a
   mid-range phone.

### Cartridges

| ID           | Title      | Inspired by       | Core OOP showcase                                   |
|--------------|------------|-------------------|-----------------------------------------------------|
| `serpent`    | SERPENT    | classic phone snake | `GridGame` multilevel inheritance, `std::deque`, CRTP |
| `minefield`  | MINEFIELD  | mine sweeping     | BFS with `std::queue`, `std::set`, score-order strategy |
| `stackfall`  | STACKFALL  | falling blocks    | `std::array` rotation tables, 7-bag `std::shuffle`  |
| `flapwing`   | FLAPWING   | tap-to-fly        | `PhysicsGame`, diamond with virtual inheritance     |
| `silverball` | SILVERBALL | pinball           | `Collider` polymorphism, table file factory         |

## 2. Platform architecture

### 2.1 How C++ ends up on a phone

Emscripten compiles the C++ code to WebAssembly. A build produces four files that any static host
can serve; there is no server-side code.

| File          | Origin                                         |
|---------------|------------------------------------------------|
| `index.html`  | generated from our `web/shell.html`            |
| `index.js`    | loader glue **generated** by Emscripten        |
| `index.wasm`  | our compiled C++                               |
| `index.data`  | the `assets/` folder, packed by `--preload-file` |

The same source also builds as a native desktop app (SDL2) for fast iteration, debugging and tests.

### 2.2 Layers

```
┌────────────────────────────── games/ ───────────────────────────────┐
│  SerpentGame  MinefieldGame  StackfallGame  FlapwingGame  SilverballGame │
│        └──── GridGame ────┘           └──── PhysicsGame ────┘        │
│                          Game (abstract)                             │
├──────────────── scenes/  ·  ui/  ·  device/ ────────────────────────┤
│  SceneStack, Boot/Menu/Game/Pause/ScoreEntry/Settings/Error scenes   │
│  Widget tree · DeviceShell + ILayout (portrait / landscape)          │
├──── gfx/ ──────── input/ ───────── audio/ ──────── io/ ─────────────┤
│  Renderer        InputState        Channels       TextReader, IniFile│
│  Font, Sprite    IInputSource      Mixer          Binary I/O, Scores │
│  Compositor      Gestures          SfxLibrary     IPersistence       │
├────────────────────────────── core/ ────────────────────────────────┤
│  App · Clock · Vec2 · Rect · Random · Log · Error · Signal · RingBuffer │
├──────────────────────────── platform/ ──────────────────────────────┤
│  SdlPlatform: window/canvas, texture, events, audio device, timer   │
│  Web extras: canvas sizing, visibility, vibrate, fullscreen, IndexedDB│
│  ← the only code that includes SDL or Emscripten headers            │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.3 Why SDL2

SDL2 has a long-standing, stable Emscripten port (`-sUSE_SDL=2`) and identical behaviour natively.
Emscripten's SDL3 port still carries an "experimental" warning, so SDL2 is the safer choice. We use
SDL for exactly five things: the window/canvas, one streaming texture, input events, the audio
device and a high-resolution timer. Everything visible or audible is generated by our C++.

### 2.4 Targets and budgets

| Item                   | Target                                              |
|------------------------|-----------------------------------------------------|
| Browsers               | Current Chrome/Edge/Firefox/Safari; Android Chrome, iOS Safari 16+ |
| Exceptions             | Native Wasm exception handling (`-fwasm-exceptions`) |
| Frame rate             | 60 fps on a mid-range phone; simulation fixed at 60 Hz |
| Download               | < 2 MB for all four files (measure `-O2` vs `-Os`)  |
| Startup                | < 2 s to boot screen on 4G                          |
| Per-frame allocations  | 0 in steady state                                   |
| Threads                | none (avoids cross-origin isolation requirements)   |

## 3. The NEOBRICK device

### 3.1 Surfaces

- **LCD** — 160×144 pixels, one byte per pixel holding a shade index:
  `0 Paper` (lightest) · `1 Light` · `2 Dark` · `3 Ink` (darkest). All games render here.
- **Device surface** — the whole console face (case, bezel, LCD, buttons) drawn at a low logical
  resolution and scaled up by an integer factor.
  - Portrait: width **180**, height **300–400** (stretches to fit the phone's aspect ratio).
  - Landscape: height **180**, width **320–420**.

### 3.2 Integer scaling

```
phys     = canvas backing size in device pixels (CSS size × devicePixelRatio)
base     = 180×300 (portrait) or 320×180 (landscape)
scale    = max(1, min(phys.w / base.w, phys.h / base.h))        // integer division
surface  = portrait:  180 × clamp(phys.h / scale, 300, 400)
           landscape: clamp(phys.w / scale, 320, 420) × 180
offset   = (phys − surface × scale) / 2                          // letterbox in case colour
```

Example: a 390×844 CSS-pixel phone at 3× density → 1170×2532 physical → scale 6 → surface 180×400 →
drawn at 1080×2400, centred.

Touch to surface coordinates: `s = (finger × phys − offset) / scale`. Surface to LCD:
`lcd = s − layout.lcdOrigin()`.

### 3.3 Portrait layout (180 × H)

```
 y=0  ┌────────────────────────────────────┐
      │ ● PWR                              │
  12  │ ┌────────────────────────────────┐ │  bezel 172×164 at (4,12), Ink with Dark inner rim
      │ │   ┌────────────────────────┐   │ │
      │ │   │                        │   │ │  LCD 160×144 at (10,20)
      │ │   │          LCD           │   │ │
      │ │   │                        │   │ │
      │ │   └────────────────────────┘   │ │
 176  │ └────────────────────────────────┘ │
      │          N E O B R I C K           │  wordmark at y≈180, mini font
      │                                    │  ← flexible gap (tall phones get more room)
 H−124│      ▲                    ( A )    │
      │    ◀ ✚ ▶             ( B )         │
      │      ▼                             │
      │      [SELECT] [START]      ╱╱╱╱    │  speaker slots
 H    └────────────────────────────────────┘
```

Controls are anchored to the bottom edge (`ctrlTop = H − 124`):

| Control | Drawn                                  | Touch hit zone                                    |
|---------|----------------------------------------|---------------------------------------------------|
| D-pad   | centre (40, ctrlTop+44), 13-px arms, 39-px span | circle r=30; direction from angle in 4 × 90° sectors; dead zone r<5 keeps last direction |
| A       | circle r=11 at (148, ctrlTop+34)       | r=17, nearest button wins                         |
| B       | circle r=11 at (118, ctrlTop+50)       | r=17                                              |
| SELECT  | pill 24×8 at (62, ctrlTop+96)          | 32×20                                             |
| START   | pill 24×8 at (96, ctrlTop+96)          | 32×20                                             |

Hit zones are deliberately larger than the drawn shapes. A **left-handed** setting mirrors the
control block horizontally.

### 3.4 Landscape layout (W × 180)

LCD centred at `((W−160)/2, 18)`. D-pad centred in the left margin at y=100, A/B mirrored in the
right margin, SELECT/START as 20×6 pills centred below the LCD at y=166. Same hit-zone rules.

### 3.5 Palettes

LCD palettes (index 0 → 3). Stored in `assets/data/palettes.txt` and selectable in Settings.

| Name   | 0 Paper   | 1 Light   | 2 Dark    | 3 Ink     |
|--------|-----------|-----------|-----------|-----------|
| Moss   | `#C9D69A` | `#8BA35A` | `#3E5C38` | `#1E2A1E` |
| Ash    | `#E3E6DD` | `#A3A8A0` | `#555B57` | `#222222` |
| Ember  | `#FFD49A` | `#D9822B` | `#7A3B12` | `#2B1408` |
| Tide   | `#D6F0F5` | `#6FA3C9` | `#2E4A7A` | `#0F1A2E` |
| Berry  | `#F5C8DA` | `#C45A8C` | `#6B2153` | `#2A0F24` |
| Stark  | `#FFFFFF` | `#AAAAAA` | `#555555` | `#000000` | (high-contrast, accessibility)

Case themes (an 8-colour palette for the shell only): **Brick** (warm grey), **Grape** (translucent
purple look via dithering), **Teal**, **Bone**, **Night**. Buttons, labels and shadows are defined
per theme.

### 3.6 Physical feedback

- Pressed buttons draw 1 px lower with a darker face and no drop shadow.
- The power LED is lit while sound is on.
- Optional haptic tick on each button press (see §5.6).

## 4. Rendering

### 4.1 Pixel buffers

| Class               | Ownership                          | Used for                     |
|---------------------|------------------------------------|------------------------------|
| `gfx::PixelBuffer`  | raw `Shade*` array (`Shade` is a 1-byte `enum class`) — **Rule of Five, on purpose** | LCD and sprites (shade indices) |
| `gfx::RgbaSurface`  | `std::vector<std::uint32_t>` — Rule of Zero | composed device face        |

Same job, two ownership styles; the contrast is documented in `docs/oop-map.md`.

```cpp
class PixelBuffer {                               // Demonstrates: Rule of Five, RAII
public:
    PixelBuffer() noexcept = default;
    PixelBuffer(int w, int h, Shade fill = Shade::Paper);
    PixelBuffer(const PixelBuffer& other);                    // deep copy
    PixelBuffer(PixelBuffer&& other) noexcept;                // steal pointer
    PixelBuffer& operator=(const PixelBuffer& other);         // copy-and-swap
    PixelBuffer& operator=(PixelBuffer&& other) noexcept;
    ~PixelBuffer();
    friend void swap(PixelBuffer& a, PixelBuffer& b) noexcept;

    [[nodiscard]] int width() const noexcept;
    [[nodiscard]] int height() const noexcept;
    Shade& operator()(int x, int y) noexcept;                 // unchecked
    Shade  operator()(int x, int y) const noexcept;
    Shade& at(int x, int y);                                  // throws std::out_of_range
    std::span<Shade> row(int y) noexcept;
private:
    int w_ = 0, h_ = 0;
    Shade* data_ = nullptr;
};
```

### 4.2 Renderer

```cpp
class Renderer {                     // Demonstrates: function overloading
public:
    explicit Renderer(PixelBuffer& target);
    void clear(Shade s = Shade::Paper);
    void pixel(Vec2i p, Shade s);
    void line(Vec2i a, Vec2i b, Shade s);                     // Bresenham
    void rect(const Rect& r, Shade s);                        // outline
    void fill(const Rect& r, Shade s);
    void fill(const Rect& r, Dither d, Shade a, Shade b);     // 2-tone ordered dither
    void circle(Vec2i c, int r, Shade s);                     // midpoint
    void fillCircle(Vec2i c, int r, Shade s);
    void draw(const Sprite& s, Vec2i at, Flip f = Flip::None);
    void draw(const SpriteSheet& sheet, int frame, Vec2i at, Flip f = Flip::None);
    void text(std::string_view str, Vec2i at, const TextStyle& style = {});
    void setClip(const Rect& r);   void resetClip();
    void setCamera(Vec2i offset);  // world → screen for scrolling games
};
```

All operations clip to the current clip rect. `TextStyle` uses a fluent builder:
`TextStyle{}.font(Font::Mini).shade(Shade::Ink).align(Align::Center).inverted()`.

### 4.3 Fonts and sprites

- **Main font** `pixel5x7.fnt`: 5×7 glyphs in a 6×8 cell → 26 columns × 18 rows on the LCD.
- **Mini font** `mini3x5.fnt`: 3×5 in a 4×6 cell, digits/uppercase for HUDs.
- Glyphs and sprites are original, drawn as text grids (§10.6). Sprite pixels are `0–3` or
  transparent.

### 4.4 Present pipeline

```
Game/Scene draws ─▶ LCD PixelBuffer (shade indices)
                     │ palette lookup + active LcdEffect
                     ▼
DeviceShell (cached, redrawn only when dirty) ─▶ RgbaSurface (device face)
                     │ SDL_UpdateTexture (one streaming texture)
                     ▼
SDL_RenderCopy into the integer-scaled destination rect ─▶ SDL_RenderPresent
```

**Canvas sizing on the web.** On every resize/orientation change, `WebPlatform` reads the canvas CSS
size (`emscripten_get_element_css_size`) and `emscripten_get_device_pixel_ratio()`, sets the backing
store to CSS size × ratio, then the active `ILayout` recomputes. Phase 0 includes a spike to confirm
the exact call sequence with SDL2 on real phones; record the result here.

*Phase 0 spike result (pending real-phone confirmation):* SDL2's Emscripten backend already does
this sequence, so no extra platform code is needed:

1. `shell.html` sizes the canvas with CSS only (`width: 100vw; height: 100dvh`).
2. Create the window with `SDL_WINDOW_RESIZABLE | SDL_WINDOW_ALLOW_HIGHDPI`. Because the CSS size
   differs from the requested size, SDL marks the canvas as externally sized and, on creation and
   on every browser resize, reads the canvas CSS size, multiplies by
   `emscripten_get_device_pixel_ratio()` and sets the backing store to that.
3. Each frame, `SDL_GetRendererOutputSize` returns the backing store size in device pixels; use it
   (not `SDL_GetWindowSize`, which is CSS pixels) for the integer scale and letterbox offset.
4. `SDL_HINT_RENDER_SCALE_QUALITY = "nearest"` before creating the texture, plus
   `image-rendering: pixelated` on the canvas, keeps every edge sharp.

If a phone shows blur, fall back to the manual sequence above from a resize callback.

### 4.5 Effects

| Effect           | How                                                            |
|------------------|----------------------------------------------------------------|
| Palette fade     | Remap shade indices toward Paper or Ink in 4 steps × 4 frames  |
| LCD ghosting     | Blend 35 % of previous frame's RGB (classic slow-LCD smear)    |
| Pixel grid       | Overlay texture with 1-px darker gaps; only when scale ≥ 4     |
| Screen shake     | Camera offset decaying over 10 frames                          |
| Flash            | Invert LCD for 2 frames                                        |

Ghosting, grid and "none" are `LcdEffect` strategy subclasses chosen in Settings.

## 5. Input

### 5.1 Buttons and state

```cpp
enum class Button : std::uint8_t { Up, Down, Left, Right, A, B, Start, Select };
using ButtonSet = std::bitset<8>;

class InputState {
public:
    [[nodiscard]] bool held(Button b) const;
    [[nodiscard]] bool pressed(Button b) const;    // went down this step
    [[nodiscard]] bool released(Button b) const;   // went up this step
    [[nodiscard]] std::optional<Vec2i> lcdTap() const;    // tap position on the LCD, if any
    [[nodiscard]] std::optional<Gesture> gesture() const; // swipe / long-press on the LCD
};
```

Edges (`pressed`/`released`) are delivered to the first fixed step of a frame only.

### 5.2 Platform events

```cpp
using PlatformEvent = std::variant<KeyEvent, FingerEvent, MouseEvent,
                                   ResizeEvent, VisibilityEvent, QuitEvent>;

// dispatch with the overloaded-lambda idiom (variadic template + multiple inheritance)
template<class... Fs> struct overloaded : Fs... { using Fs::operator()...; };
std::visit(overloaded{
    [&](const KeyEvent& e)    { keyboard_.handle(e); },
    [&](const FingerEvent& e) { touch_.handle(e); },
    ...
}, event);
```

### 5.3 Input sources (runtime polymorphism)

```cpp
class IInputSource {
public:
    virtual ~IInputSource() = default;
    virtual void handle(const PlatformEvent& e) = 0;
    virtual void contribute(ButtonSet& held) const = 0;    // OR-ed into the frame's state
};
class KeyboardSource final : public IInputSource { ... };
class TouchSource    final : public IInputSource { ... };  // multi-touch, layout hit zones
class MouseSource    final : public IInputSource { ... };  // desktop: mouse acts as one finger
```

`InputManager` owns `std::vector<std::unique_ptr<IInputSource>>` and merges them each frame.

### 5.4 Touch rules

- Each finger is tracked by its SDL finger id → the button it currently covers.
- Sliding a finger from one button to another releases the first and presses the second.
- On the D-pad, the direction comes from the angle to the centre, so a thumb can roll between
  directions without lifting.
- Taps inside the LCD rect produce `lcdTap`; `GestureRecognizer` turns LCD drags into swipes
  (≥ 12 LCD px within 250 ms) and holds into long-presses (≥ 350 ms, ≤ 3 px movement).
- SDL synthesizes mouse events from touches; ignore mouse events whose `which == SDL_TOUCH_MOUSEID`
  to avoid double input.

### 5.5 Keyboard map

| Button | Keys                 |
|--------|----------------------|
| D-pad  | Arrow keys, WASD     |
| A      | X, K                 |
| B      | Z, J                 |
| START  | Enter, Esc           |
| SELECT | Right Shift, Backspace |

### 5.6 Haptics

10 ms tick on button press (toggle in Settings), 40 ms on line clears/game over, via
`emscripten_vibrate`. iOS Safari does not support the Vibration API, so it silently does nothing
there; native builds no-op.

## 6. Audio

A small chip-style synthesizer, 22,050 Hz mono, 16-bit.

```
Channel (abstract)                 virtual float sample() noexcept = 0
 ├── PulseChannel   ×2             duty 12.5 / 25 / 50 / 75 %, frequency sweep
 ├── WaveChannel    ×1             32-step 4-bit wavetable
 └── NoiseChannel   ×1             15-bit LFSR, short/long mode
Envelope                            attack/decay/sustain/release in 1/64-s ticks
Mixer                               owns channels, master volume 0–7, soft clip
```

- **Thread safety.** Natively, SDL calls the audio callback on its own thread. Game code never
  touches channels directly; it pushes `AudioCommand`s into a lock-free single-producer/
  single-consumer `RingBuffer<AudioCommand, 64>` (`std::array` + `std::atomic` indices). The
  callback drains it. The callback is `noexcept` and never allocates.
- **Sound effects** are data in `assets/audio/sfx.txt` (§10.7). `SfxLibrary` parses them once.
- **Music** (stretch goal): a tiny tracker format `.trk`, one menu theme.
- **Unlock.** Browsers keep audio suspended until a user gesture. The boot screen says PRESS START;
  the first touch/key opens and unpauses the SDL audio device.
- **Visibility.** Audio pauses when the page is hidden.

## 7. App, main loop and scenes

### 7.1 Start-up

```
main()
 └─ static std::unique_ptr<App> app = make_unique<App>()   // never on main()'s stack
     ├─ SdlPlatform init                       (throws PlatformError)
     ├─ persistence.restoreAll(onDone)         (web: IndexedDB → /save, async, ≤1.5 s timeout)
     ├─ load settings.ini, scores.dat          (recover from corruption, §9.4)
     ├─ AssetCache preload: fonts, shell sprites, palettes
     ├─ register the five games in GameRegistry
     ├─ scenes.push<BootScene>()
     └─ web:    emscripten_set_main_loop_arg(&App::frameThunk, app.get(), 0, true)
        native: while (app->running()) app->frame();
```

### 7.2 Frame

```cpp
void App::frame() noexcept {
    try {
        platform_.pumpEvents(input_);                  // PlatformEvent → sources
        accumulator_ += std::clamp(clock_.delta(), 0.0, 0.25);
        while (accumulator_ >= kStep) {                // kStep = 1/60 s
            scenes_.update(input_.state(), kStep);
            input_.endStep();                          // clears edges after first step
            accumulator_ -= kStep;
        }
        scenes_.draw(renderer_);
        compositor_.present(lcd_, shell_, layout());
    } catch (const nb::Error&) {
        scenes_.showError(std::current_exception());
    } catch (const std::exception&) {
        scenes_.showFatal(std::current_exception());
    }
}
```

When the page is hidden (`emscripten_set_visibilitychange_callback`), the active game auto-pauses and
the accumulator resets so the game doesn't fast-forward on return.

### 7.3 Scenes

| Scene             | Purpose                                                       | Overlay? |
|-------------------|---------------------------------------------------------------|----------|
| `BootScene`       | Logo slides down, two-note chime, blinking PRESS START, audio unlock | no |
| `MenuScene`       | Cartridge carousel, best score under each, SELECT → Settings  | no       |
| `GameScene`       | Hosts one `Game`, handles START → pause, game over → scores   | no       |
| `PauseScene`      | Resume / Restart / Save & Quit / Quit over a dithered game    | yes      |
| `ScoreEntryScene` | Arcade-style 3-initial entry                                  | no       |
| `SettingsScene`   | Palette, case theme, LCD effect, volume, haptics, layout, left-handed, reset data | no |
| `ErrorScene`      | Shows the nested error chain; A → menu                        | no       |

```
Boot ──START──▶ Menu ──A──▶ GameScene ──START──▶ Pause (overlay)
                 ▲ │SELECT        │ game over        │ Quit / Save & Quit
                 │ ▼              ▼                  │
                 │ Settings   ScoreEntry (if top 10) │
                 └──────────────────┴────────────────┘
any scene ── nb::Error ──▶ ErrorScene ──A──▶ Menu
```

`SceneStack` stores `std::vector<std::unique_ptr<Scene>>` and applies push/pop/replace requests
**after** the update pass (deferred), so a scene can safely remove itself. Overlays draw the scene
beneath them first.

```cpp
class Scene {                                   // Demonstrates: abstract class, pure virtuals
public:
    virtual ~Scene() = default;
    virtual void onEnter() {}
    virtual void onExit() {}
    virtual void update(const InputState& in, Seconds dt) = 0;
    virtual void draw(Renderer& r) const = 0;
    [[nodiscard]] virtual bool isOverlay() const { return false; }
};

class SceneStack {
public:
    template<class S, class... Args>            // Demonstrates: perfect forwarding
    void push(Args&&... args) {
        pending_.push_back(Op::push(std::make_unique<S>(std::forward<Args>(args)...)));
    }
    void pop();  void replace(std::unique_ptr<Scene> s);
    void update(const InputState& in, Seconds dt);   // updates top, then applies pending_
    void draw(Renderer& r) const;
};
```

### 8.2 Game hierarchy (`src/games/`)

```
                    Identifiable (debugName)
                     ▲ virtual          ▲ virtual
              IUpdatable             IDrawable
                     ▲                   ▲
                     └──── GameObject ───┘          (diamond, one Identifiable subobject)
                              ▲
              ┌───────────────┼──────────────────┐
           Pipe, Bird      TableElement       Particle …
                             ▲
             Bumper, Slingshot, DropTarget, Rollover, Flipper, Plunger, Wall


                              Game (abstract, Template Method)
                 ┌──────────────┴───────────────┐
            GridGame (abstract)            PhysicsGame (abstract)
       ┌────────┼─────────┐                 ┌────────┴────────┐
 SerpentGame MinefieldGame StackfallGame  FlapwingGame   SilverballGame     (all final)
```

```cpp
class Game {                                          // Demonstrates: abstract base, template method
public:
    explicit Game(GameContext& ctx);
    virtual ~Game();

    void step(const InputState& in, Seconds dt);      // non-virtual: fixed algorithm
    void render(Renderer& r) const;                   //   (input → world → HUD)

    [[nodiscard]] virtual const GameInfo& info() const = 0;
    virtual void reset() = 0;
    [[nodiscard]] virtual bool isOver() const = 0;
    [[nodiscard]] virtual std::uint32_t score() const = 0;
    [[nodiscard]] virtual std::string scoreTableKey() const;   // e.g. "minefield.rookie"

    [[nodiscard]] virtual bool supportsSaveState() const { return false; }
    virtual void save(io::BinaryWriter& w) const;     // default throws ContractViolation
    virtual void load(io::BinaryReader& r);

    [[nodiscard]] static int liveInstances() noexcept;   // static data member counter
protected:
    virtual void handleInput(const InputState& in) = 0;
    virtual void updateWorld(Seconds dt) = 0;
    virtual void drawWorld(Renderer& r) const = 0;
    virtual void drawHud(Renderer& r) const;          // default: score, top-left, mini font
    GameContext& ctx_;                                // events, rng, assets, settings
private:
    static inline int liveInstances_ = 0;
    friend class GameTestAccess;                      // friend class: tests inspect internals
};

class GridGame : public Game {                        // multilevel inheritance
protected:
    GridGame(GameContext& ctx, Vec2i cells, int cellPx, Vec2i origin);
    [[nodiscard]] Vec2i cellToScreen(Vec2i cell) const;
    [[nodiscard]] std::optional<Vec2i> screenToCell(Vec2i lcd) const;
    void drawFrame(Renderer& r) const;
};

class PhysicsGame : public Game {
protected:
    PhysicsGame(GameContext& ctx, int substeps);
    void updateWorld(Seconds dt) final;               // final: subclasses use simulate()
    virtual void simulate(Seconds subDt) = 0;
    std::vector<std::unique_ptr<GameObject>> objects_;
    Camera camera_;
};
```

`Counted<T>` (CRTP) gives each concrete game its own instance counter:
`class SerpentGame final : public GridGame, private Counted<SerpentGame>`.

`Grid<T>` is a class template backed by `std::vector<T>` with `operator()(x, y)`, bounds-checked
`at()` (throws `std::out_of_range`), `neighbours(p)` and `begin()/end()` so it works with range-for
and STL algorithms.

## 9. Error handling

### 9.1 Hierarchy (`src/core/Error.hpp`)

```
std::exception
 ├── std::runtime_error
 │    └── nb::Error                  code(), context() — short what() for a 26-column screen
 │         ├── nb::PlatformError     SDL init, canvas, audio device
 │         ├── nb::AssetError
 │         │    └── nb::ParseError   file(), line(), column()
 │         ├── nb::SaveError
 │         │    ├── nb::CorruptSaveError       bad magic or CRC
 │         │    └── nb::VersionMismatchError   newer format than we understand
 │         └── nb::UnknownGameError
 └── std::logic_error
      └── nb::ContractViolation      programmer error: bad arguments, misuse
```

Also expected from the standard library: `std::out_of_range` (`PixelBuffer::at`),
`std::bad_alloc` (caught only at the top level).

### 9.2 Where exceptions are caught

| Boundary                 | Catches                         | Result                                      |
|--------------------------|---------------------------------|---------------------------------------------|
| `main()` start-up        | `PlatformError`, `std::exception` | message to console; nothing else can run  |
| `App::frame()`           | `nb::Error`, `std::exception`   | `ErrorScene`; app keeps running             |
| `GameScene` start-up     | `AssetError`                    | rethrown via `std::throw_with_nested(Error{"Can't start SILVERBALL"})` |
| Save/settings load       | `SaveError`                     | recover (§9.4), show a Toast                |
| Audio callback           | everything                      | `noexcept`; never throws, outputs silence on internal failure |

`ErrorScene` walks the chain with `std::rethrow_if_nested` and uses `dynamic_cast<const ParseError*>`
to add "file:line" when available, e.g.

```
CAN'T START SILVERBALL
> TABLE ERROR
> classic.tbl:14
> unknown 'bumpr'
        A: MENU
```

### 9.3 Guarantees

- **No-throw:** destructors, moves, `swap`, all `draw()` paths, the audio callback.
- **Strong:** `HighScoreTable::submit` (work on a copy, then swap), `Settings::apply`, every file
  write (temp file + rename).
- **Basic:** everything else.

### 9.4 Recovery

| Problem                      | Action                                                            |
|------------------------------|-------------------------------------------------------------------|
| `scores.dat` corrupt         | rename to `scores.dat.bak`, start an empty table, Toast "SCORES RESET" |
| `scores.dat` newer version   | don't overwrite; run without saving scores, Toast "SAVE FROM NEWER VERSION" |
| `settings.ini` bad line      | ignore that key, use default, log the `ParseError`                |
| `.sav` unreadable            | delete the save state, start a fresh game                          |
| asset missing or malformed   | `ErrorScene` → menu (only that cartridge is affected)              |

## 10. Files and persistence

### 10.1 Locations

| Path                    | Access     | Notes                                                    |
|-------------------------|------------|----------------------------------------------------------|
| `/assets/...`           | read-only  | web: preloaded into the in-memory FS; native: next to the binary |
| `Paths::saveDir()`      | read/write | web: `/save` (in-memory, mirrored to IndexedDB); native: `SDL_GetPrefPath("neobrick","neobrick")` |

### 10.2 Save files

| File                 | Format | Contents                                   |
|----------------------|--------|--------------------------------------------|
| `settings.ini`       | text   | user settings                              |
| `scores.dat`         | binary | top-10 tables for every score key          |
| `<game>.sav`         | binary | suspended game state (Phase 11)            |
| `neobrick.log`       | text   | native only, append mode; web logs to the console via `std::cout` |

### 10.3 `settings.ini`

```ini
# NEOBRICK settings
[display]
palette    = moss        # moss | ash | ember | tide | berry | stark
case       = brick
lcd_effect = ghosting    # none | ghosting | grid
[audio]
volume = 5               # 0-7
[input]
haptics      = true
layout       = auto      # auto | portrait | landscape
left_handed  = false
```

`IniFile` parses into `std::map<std::string, std::map<std::string, std::string>>` with `getline`.
Typed access `get<T>(section, key, fallback)` is a member function template with **full
specializations** for `bool`, `int` and `std::string`.

### 10.4 `scores.dat` (little-endian)

| Offset | Size | Field                                             |
|--------|------|---------------------------------------------------|
| 0      | 4    | magic `"NBHS"`                                    |
| 4      | 2    | format version (`1`)                              |
| 6      | 2    | number of tables                                  |
| …      |      | per table: `u8` key length, key bytes, `u8` entry count (≤10), then entries |
|        | 11   | per entry: 3 × `char` initials, `u32` value, `u32` Unix time |
| end−4  | 4    | CRC32 of everything before                        |

Each table has a `ScoreOrder` strategy: `HigherIsBetter` (points) or `LowerIsBetter` (Minefield
seconds). Ordering uses `std::stable_sort` so earlier entries win ties. `ScoreEntry` defines
`operator<=>` on value then time.

`BinaryWriter`/`BinaryReader` wrap `std::ofstream`/`std::ifstream` opened with `std::ios::binary`,
overload `operator<<`/`operator>>`, and delegate to `Serializer<T>`:

- primary template for arithmetic types (explicit little-endian byte order);
- full specialization `Serializer<std::string>` (length-prefixed);
- partial specialization `Serializer<std::vector<T>>` and `Serializer<std::array<T, N>>`.

### 10.5 `<game>.sav`

Header `"NBSV"`, version, game id, game's own format version, payload written by `Game::save`,
CRC32. Only one slot per game. Loaded from the menu ("CONTINUE?") and deleted when the game resumes.

### 10.6 Fonts (`.fnt`) and sprites (`.spr`)

```
# pixel5x7.fnt                      # sprites/serpent.spr
glyph A                             sprite head_right 8 8
.###.                               ........
#...#                               ..3333..
#...#                               .333333.
#####                               .33303..
#...#                               .33333..
#...#                               .333333.
#...#                               ..3333..
end                                 ........
                                    end
```

Fonts: `#` on, `.` off. Sprites: `0–3` shade, `.` transparent. `TextReader` counts lines and throws
`ParseError` with file and line for wrong row widths, unknown characters or missing `end`.

### 10.7 Data files

- `assets/data/palettes.txt` — `palette moss C9D69A 8BA35A 3E5C38 1E2A1E`
- `assets/audio/sfx.txt` — `sfx eat pulse duty=50 from=880 to=1320 ms=60 vol=12 decay=fast`
- `assets/levels/serpent_mazes.txt` — named 40×34 character grids (`#` wall, `.` floor, `S` start)
- `assets/data/stackfall.txt` — gravity table (frames per row per level), DAS, ARR, lock delay
- `assets/tables/silverball_classic.tbl` — see §11.5

### 10.8 Web persistence

```cpp
class IPersistence {                        // Demonstrates: interface + two implementations
public:
    virtual ~IPersistence() = default;
    virtual void restoreAll(std::function<void()> done) = 0;
    virtual void commit(const std::filesystem::path& file) = 0;
};
class NativePersistence final : public IPersistence { … };   // files are already on disk: no-ops
class WebPersistence    final : public IPersistence { … };   // mirrors /save ↔ IndexedDB
```

`WebPersistence` uses Emscripten's C IndexedDB API — no JavaScript written by us:

- **Boot:** for each known save file, `emscripten_idb_async_load("neobrick", name, …)`. On success
  the bytes are written to `/save/<name>` with `std::ofstream`; `done()` fires when all callbacks
  return (or after 1.5 s).
- **Commit:** after a write, read the file back with `std::ifstream` into a `std::vector<char>` and
  call `emscripten_idb_async_store`. Failures are logged and shown as a Toast; never fatal.

All game code only ever sees normal `fstream` file handling.

## 11. Games

Common to every game: START pauses, game over → score entry if it ranks, a HUD in the mini font,
sounds through `EventBus::playSfx`, deterministic with a seeded `Random`.

### 11.1 SERPENT (`GridGame`)

- **Grid:** 40×34 cells of 4 px; HUD strip 8 px at the top.
- **Modes:** *Box* (walls kill), *Wrap* (edges wrap around), *Maze* (layouts loaded from
  `serpent_mazes.txt`).
- **Speed levels 1–9**, chosen before play: step interval `0.20 s − (level−1) × 0.018 s`.
- **Food** scores `level` points. Every 5th food spawns a **bonus critter** for 5 s with a
  shrinking timer bar; it scores `level × (seconds left + 5)`.
- **Body** `std::deque<Vec2i>` (push head, pop tail). **Occupancy** `std::unordered_set<Vec2i>` with
  the `std::hash` specialization for O(1) self-collision. **Input buffer** `std::queue<Direction>`
  holding up to 2 turns, rejecting 180° reversals.
- **Controls:** D-pad, or swipe on the LCD.
- **Charm:** the head sprite opens its mouth when food is directly ahead.

### 11.2 MINEFIELD (`GridGame`)

| Difficulty | Board | Mines | Notes                               |
|------------|-------|-------|-------------------------------------|
| Rookie     | 9×9   | 10    | centred                             |
| Veteran    | 16×16 | 40    | exactly fills the 128-px play area  |
| Expert     | 30×16 | 99    | viewport scrolls horizontally       |

- 8-px cells, 16-px HUD: mines left, status face (original art), timer.
- **First reveal is always safe:** mines are placed after the first reveal, excluding its 3×3
  neighbourhood (`std::iota` candidates → `std::shuffle` → take N).
- **Flood reveal:** BFS with `std::queue<Vec2i>`; adjacency counts with `std::count_if`.
- **Chording:** A on a revealed number with matching flags reveals its neighbours.
- **Flags** kept in a `std::set<Vec2i>` (ordered, enabled by `Vec2`'s `<=>`).
- **Controls:** D-pad cursor, A reveal, B flag, SELECT toggles tap mode (dig/flag).
  Touch: tap a cell = current mode; long-press = flag.
- **Scores:** best times per difficulty, `LowerIsBetter`, keys `minefield.rookie|veteran|expert`.

### 11.3 STACKFALL (`GridGame`)

- **Well:** 10×20 of 7-px cells (70×140) at the left; right panel shows HOLD, NEXT ×3, SCORE,
  LEVEL, LINES.
- **Pieces:** 7 kinds. Rotation states are a `static constexpr std::array<std::array<Vec2i,4>,4>`
  per kind, with a small wall-kick table.
- **Randomizer:** 7-bag — `std::array` of kinds, `std::shuffle` with the game's `Random`.
  Upcoming pieces in a `std::deque`.
- **Feel:** DAS/ARR for held left/right, lock delay with a move-reset limit of 15, ghost piece
  drawn with a dither pattern, hard drop. Values come from `stackfall.txt`.
- **Line clears:** rows found with `std::all_of`, flash 3 times, then collapse.
- **Scoring:** 1/2/3/4 lines = 100/300/500/800 × level; soft drop +1 per row, hard drop +2.
  Level up every 10 lines.
- **Controls:** ◀▶ move, ▼ soft drop, ▲ hard drop, A rotate clockwise, B rotate anticlockwise,
  SELECT hold.

### 11.4 FLAPWING (`PhysicsGame`)

- **Bird:** a `GameObject` with position/velocity (`Vec2f`). Gravity ≈ 600 px/s², flap sets
  velocity to −170 px/s, terminal fall 250 px/s. Final values tuned on a phone.
- **Pipes:** `std::deque<PipePair>` recycled off the left edge; gap starts at 44 px and narrows to
  34 px; scroll speed rises slowly with score.
- **Parallax:** three `ParallaxLayer`s (clouds ×0.2, hills ×0.5, ground ×1.0).
- **Collision:** AABB with the bird's hitbox shrunk by 2 px for fairness.
- **Day/night:** palette remap every 25 points.
- **Medals** at 10 / 20 / 40 points (original designs).
- **Controls:** tap anywhere on the LCD, A, or ▲.

### 11.5 SILVERBALL (`PhysicsGame`)

- **Table:** 160×288 (two screens tall). The camera follows the ball vertically with smoothing.
- **Physics:** 4 substeps per frame (240 Hz) to prevent tunnelling; ball radius 3 px; wall
  restitution ≈ 0.5; bumpers add a kick with a minimum exit speed; flippers rotate ±30° at about
  25 rad/s and add the flipper's surface velocity at the contact point.
- **Colliders:**

```cpp
class Collider {                                       // Demonstrates: runtime polymorphism
public:
    virtual ~Collider() = default;
    [[nodiscard]] virtual std::optional<Contact> test(const Ball& b) const = 0;
};
class CircleCollider  : public Collider { … };
class SegmentCollider : public Collider { … };
class FlipperCollider final : public SegmentCollider { … };   // adds angular velocity
```

- **Table elements** (`TableElement : GameObject`, each owns a `Collider` by composition and
  overrides `virtual void onHit(Ball&, ScoreSink&)`): Wall, Bumper, Slingshot, DropTarget (groups),
  Rollover (top lanes), Flipper, Plunger, Drain.
- **Table file** `silverball_classic.tbl`:

```
# units: LCD pixels, origin top-left of the table
table    name="Classic" width=160 height=288 gravity=300
wall     points=4,0 4,250 30,272
bumper   x=60 y=70 r=7 score=100
sling    x1=28 y1=230 x2=40 y2=250 score=10
target   x=100 y=120 w=6 h=3 score=500 group=A
rollover x=50 y=18 lane=1
flipper  side=left  pivot=48,262 length=22
flipper  side=right pivot=112,262 length=22
plunger  x=152 y=270
drain    y=284
```

  `TableLoader` maps each keyword to a factory lambda in a `std::map`; unknown keywords or missing
  attributes throw `ParseError` with the line number.
- **Rules:** 3 balls; ball save for the first 10 s; completing a drop-target group raises the
  multiplier (×1→×5); lit rollovers award a bonus; end-of-ball bonus summed with `std::accumulate`.
  Timed events (ball save, light timeouts) live in a `std::priority_queue` min-heap.
- **Nudge:** SELECT nudges the table; three nudges in 5 s = TILT (flippers dead until drain).
- **Controls:** ◀ = left flipper, A = right flipper, hold ▼ to pull the plunger. Touch: tapping
  the left/right half of the LCD also works the flippers (two-thumb play).
- **Effects:** sparks are a `std::list<Particle>` pruned with `list::remove_if` (the one place a
  list is used; noted in `oop-map.md` with the trade-offs).

## 12. UI and visual style guide

- **Grid:** layouts snap to 8 px; text baselines on 8-px rows; 1-px outlines.
- **Shades:** Paper background, Ink text and outlines, Dark for secondary text and shadows, Light for
  fills and disabled items. Never more than 4 shades on the LCD.
- **Dithering:** 2×2 and 4×4 ordered (Bayer) patterns for in-between tones, shadows, overlays.
- **Selection:** inverted text block (Ink box, Paper text) with a 2 Hz blinking ▶ cursor.
- **Motion:** at most 2-px-per-frame UI movement; transitions are palette fades (4 steps).
- **Boot:** NEOBRICK wordmark slides down from above the LCD, stops at centre, a two-note chime
  plays (original), "PRESS START" blinks.
- **Menu:** one cartridge at a time, large; ◀▶ rotates the carousel (`std::rotate`), the label
  shows title and best score; A inserts the cartridge (it slides into a slot, the screen flickers,
  the game fades in).
- **Pause:** game dims to a 50 % dither; centred panel with four options.
- **Score entry:** three large letters, ▲▼ change, ◀▶ move, A confirms.
- **Copy:** uppercase, terse, max 26 characters per line.
- **Accessibility:** Stark palette, "reduce flashing" option (disables flash and shake), left-handed
  layout, adjustable volume, haptics toggle.

## 15. Risks and mitigations

| Risk                                               | Mitigation                                                    |
|----------------------------------------------------|---------------------------------------------------------------|
| Blurry pixels from canvas/DPR mismatch             | Phase 0 spike on real phones; integer scaling only            |
| iOS Safari quirks (no vibration, limited fullscreen, audio unlock) | Features degrade silently; audio unlock on first tap; optional home-screen manifest |
| Exceptions not caught in the web build             | `-fwasm-exceptions` on compile **and** link; Phase 0 test     |
| Touch latency / missed multi-touch                 | Process finger events directly; test two-thumb input in Phase 2 |
| Pinball physics tunnelling or jitter               | Substeps, swept tests at max speed, unit tests                |
| IndexedDB unavailable (private mode)               | Persistence errors are non-fatal; game still runs            |
| Scope creep (music, extra tables)                  | Marked as stretch goals in `phases.md`                        |
| OOP features feeling bolted on                     | Every concept is mapped to a real responsibility in §13; review in Phase 13 |

## 16. Implementation notes and deviations (October 2026)

Recorded while building every phase, so the document matches the code.

| Area | Change | Why |
|------|--------|-----|
| Web shell | `web/shell.html` has one line of config script: `var Module = { canvas: … }` | SDL2 hard-codes the `#canvas` selector and Emscripten resolves it only through `Module.canvas`; there is no C API for it. Approved and noted in `CLAUDE.md`. |
| Layers | `App` (in `core/`) is the composition root and includes every layer; platform headers use core value types (`Vec2`, `Rect`, `PlatformEvent`) and `io::IPersistence` | Something has to wire the layers together; keeping it in one class keeps the rule true everywhere else |
| Scenes | `Scene::onResume()` added, called when the scene above is popped | The menu must refresh best scores and reset its insert animation after a game closes |
| Game API | `Game::result()` (nullopt = run doesn't count, e.g. a lost MINEFIELD), `isPlaying()` (false on a game's own setup screen, so START isn't pause), `saveVersion()` | Needed by `GameScene` for score entry, pause and save files |
| Game context | `GameContext{Random&, EventBus&, AssetCache&, const SettingsValues&}` | Exactly what games use; tests build one headless (`tests/TestWorld.hpp`) |
| Events | `EventBus` has `playSfx(string_view)`, `vibrate(int)`, `toast(string_view)`; `scoreChanged`/`gameOver` dropped | Nothing listened to them; `GameScene` polls `isOver()` |
| Scores | `HighScoreTable` is one table; `ScoreBook` owns all tables and `scores.dat` | Keeps the sorted-table invariant separate from the file format |
| Grid | `Grid<bool>` is rejected by a `static_assert`; use `Grid<std::uint8_t>` | `std::vector<bool>` hands out proxies, so `T&` access breaks |
| SILVERBALL | Elements talk to the game through a small `Rules` interface (`award`, `sound`, `spark`, `targetDown`, `rolloverLit`) | Elements stay independent of `SilverballGame`; tests can call `onHit` directly |
| Fonts | `.fnt` files start with `size <w> <h>`; the space glyph is `glyph space` | Two font sizes share one loader |
| STACKFALL data | `stackfall.txt`: `gravity <frames per row by level…>`, `das`, `arr`, `lock`, `lock_resets` | Tuning without recompiling |
| Settings | `[display] reduce_flashing = true|false` | Accessibility option from §12: steady line-clear rows, no blinking snake |
| Input | Input is sampled only on frames that run at least one fixed step | On 120 Hz screens half the frames run no step; sampling there swallowed press edges |
| Keyboard | Left Shift also maps to SELECT; F1 toggles the debug overlay | Laptop keyboards; SELECT+START also toggles it |
| Error screen | File and line are shown on separate lines | `SILVERBALL_CLASSIC.TBL:16` doesn't fit 26 columns |
| Phase 4 | No `DemoGame` | The five real games were built in the same pass |
| Persistence | `IPersistence::remove()` added | Deleted save states must also leave IndexedDB |
